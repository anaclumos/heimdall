Bygge GitHub med Ruby on Rails​

Original. GitHub.com er skrevet med Ruby on Rails og vedlikeholdes av over tusen ingeniører med nesten 2 millioner kodelinjer. Selskapet oppgraderer til den nyeste Rails commit ukentlig med pull-forespørsler og revisjonsgjennomganger. Fordelene med disse oppgraderingene inkluderer bedre håndtering av databasetilkoblinger og raskere visningsgjengivelse, forbedret sikkerhet og lavere risiko for ukjente problemer. Testing av de nyeste versjonene identifiserer og løser problemer før utgivelse. Innlegget er en personvernerklæring fra GitHub, som inneholder informasjon om produktfunksjoner, sikkerhet, historier, priser, ressurser, utvikler-API, partnere, plattform og støtte. Innlegget ser ikke ut til å ha noen ny informasjon eller hendelser, og det er uklart hvorfor det får oppmerksomhet.

Discussion Service. GitHub bygget om plattformen sin med Ruby on Rails, noe som vekket interesse for dens potensielle innvirkning på Rails-økosystemet og kravene til testdekning. Brukere fremhever utfordringer med å mestre Ruby, for eksempel ekstrem testdekning og potensial for fremtidige kodefeil. Noen brukere foreslår å bruke Sorbet for sterkere kontrolltyper. GitHubs bruk av Crystal-språk og Rubys metaprogrammeringspotensial blir rost, mens noen kritiserer Rubys datavitenskapelige rom. Microsofts nylige oppgradering av Githubs Rails-plattform fra versjon 2.3 til 3 bød på utfordringer, men statisk typing hjelper oppgraderinger. Utviklere reflekterer over avveiningene mellom teknologiske trender og etablert stabilitet, og noen bemerker at Rails er brukervennlig, men at visningslaget henger etter. Rammeverksoppgraderinger gjøres mest effektivt gradvis, med god testing på plass. Mange organisasjoner ser på oppdatering av IT-infrastruktur som viktig, GitHubs testfunksjoner får skryt, og Sorbet brukes av GitHub for Ruby og Rails.
