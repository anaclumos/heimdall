Mullvad ブラウザ​

Mullvad VPN と Tor Project が共同で、大量監視に対抗する Mullvad Browser を開発；Mullvad VPN をジオブロッキング回避に使うことに懐疑派が懸念を表明；Mullvad VPN をサポートする Tor ブラウザという Firefox フォークが利用可能；オープンソースへの取り組みとシームレスな有料モデルで Mullvad が賞賛される；Mullvad Browser はフィンガープリンティングに対抗する技術を備えている；オンライントラッキングやデータ収集から保護することが目的である；Mullvad はフィンガープリンティングに対抗するためにプライバシー重視のブラウザを無料で公開した；Mullvad の VPN は VPN をブロックするウェブサイトをバイパスできる；Mullvad Browser は Tor Network と併用してもしなくても使えるようデザインされている。 Discussion Service、記事。

Pandas 2.0​

Pandas チームは、新機能、バグフィックス、パフォーマンス改善を含むバージョン 2.0.0 をリリースしました。既存のコードは、まず Pandas 1.5.3 にアップグレードしてください。Polars はより高速ですが、Pandas は進化するモデルに取り組むアナリストやエンジニアにとって依然として価値があります。Sklearn は、Polars と DuckDB を Pandas にシームレスに相互運用するキャスティングを提供しています。Pandas の 2.0 リリースでは、矢印特有の dtypes の一般的なサポートが導入されています。自動キャストやオブジェクトとしての文字列、NaN が導入された際に整数が浮動小数点になることは、一部のユーザーにとって大きな不満となっています。Pandas は QOL を向上させ、Copy-on-Write を明示的に有効にしています。Pandas は R の基本データフレームからインスピレーションを得ていますが、plyr と data.table から影響を受けています。Python プログラマは、高価な Stata の代わりに、製薬のような分野でも使える新しいオープンソースライブラリを手に入れました。 Discussion Service、記事。

Safari のリリースは開発地獄​

Safari 16.4 では、Compression Streams API と Service Workers の問題により、Construct に問題が発生し、公開されているすべてのコンテンツが壊れました。Apple のリリースプロセスにおける透明性の欠如とアップデートの遅延は、開発者の不満につながっています。さらに、Safari は OffscreenCanvas のサポートを追加しましたが、これは 2D コンテキストのみをサポートするため、既存の Web コンテンツが壊れる原因となります。開発者の間では、Chrome や Firefox を代替とする動きが強まっています。一方、Chrome の一時的なオリジン試験とハードウェア API の実装は、Safari と Firefox の開発者の反対を招いた。また、バグや将来の製品に関する Apple の透明性の欠如や、アプリストアのガイドラインも批判されている。Safari のバグや一貫性のないパフォーマンスに対応した開発は困難であり、回避策が必要であったり、他のブラウザとの互換性を犠牲にすることもあります。ユーザーは、Safari でワークフローが機能しない場合や、複数のサイトが同時に壊れた場合、他のブラウザに乗り換えるかもしれません。 Discussion Service、記事。

超高速 LZ コーデックによるニアロスレス画像フォーマット​

Richard Geldreich は、新世代の高速 LZ コーデックから構築された、シンプルな超高速ロッシーまたはロスレスに近い画像コーデックのアイデアを紹介し、より多くのまたは長いマッチを導入することで目に見えるアーティファクトを最小化します。ロスレスなフレームバッファ圧縮は、MSAA や SSAA にとって重要である。また、PNG のような画像コーデックは、マルチスレッドや GPU デコードではうまく動作しません。画像を前処理することで、反転ステップを必要とせず、高速な LZ コーデックによる圧縮を改善することができます。高速なデコードと高圧縮を両立する Zstd は、LZ4 前処理の代替となり得る。ゲームのダウンロードと物理メディアによる CO2 排出量については、まだ議論が続いています。改善案としては、プログレッシブ JPEG やウェーブレットなどがあるが、圧縮率やメモリ効率を犠牲にする可能性がある。 Discussion Service、記事。

最先端のオープンソースチャットボット「Vicuna-13B」、モデルウェイトを公開しました。​

最近公開されたオープンソースのチャットボット「Vicuna-13B」のモデルウェイトは、デルタウェイトとして LLaMA モデルライセンスに準拠しています。NN ウェイトが著作権で保護されていないことを主張する llama-dl への DMCA テイクダウン要求により、限定的なモデルリリースが将来的に制限される可能性があります。Facebook と関係のない研究者は、オリジナルの Vicuna-13B モデルの重みを所有し、使用することが許可されています。一連の微調整を含むこのモデルは、約 60GB の CPU RAM を必要としますが、64GB RAM を使用した CPU のみのモードでも実行可能です。このモデルの大規模な検索演算は、時間とエネルギーを節約し、より良い結果につながります。4 ビット量子化されたモデルの精度は、元のモデルよりも低くなります。ML モデルの重みは、モデルが「学習」した内容を表し、モデルが正しく機能するために不可欠なものです。 Discussion Service、記事。

オランダの空軍基地でアメリカの核兵器事故があったのか？​

ロスアラモス国立研究所から、EOD 担当者が曲がった B61 核爆弾のようなものを検査している画像が現れましたが、後に訓練時のものであることが確認されました。オランダの空軍基地で米国の核兵器の事故は確認されていないが、LANL の最近の写真によると、C-17A でボルケル空軍基地に保管されているすべての爆弾を移動できるようだ。破損した B61 爆弾の写真がネット上で出回っているが、真偽の確認や物理パッケージが含まれているかどうかの確認は取れていない。テキサス州の写真も出回り、事故の可能性について疑問を投げかけている。全ては、政府が情報セキュリティプロトコルを施行することの重要性を論じている。 Discussion Service、記事。
