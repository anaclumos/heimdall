2024-06-07

建议专业人士取消 Adobe，因为 NDA 存在信任问题​

  • Wetterschneider 在推特上建议专业人士，尤其是那些签订了 NDA（保密协议）或处理专有文件的专业人士，取消 Adobe 服务并删除其应用程序。
  • 这条推文声称 Adobe 不可信，但没有提供具体的理由或证据。

反应​

  • 论坛用户批评 Adobe 根据新的服务条款收取取消费和广泛的数据访问权，分享规避费用的策略，并表达了对隐私的担忧。
  • 与谷歌和微软的比较凸显了政策模糊和过度的趋势，尽管由于 Adobe 的主导地位，在转换过程中面临挑战，但仍对 GIMP、Krita 和 Affinity 等替代品进行了讨论。
  • 讨论了 Adobe 条款的法律影响，包括与客户协议的潜在冲突和合同条款的可执行性，强调了道德问题和更好的开源解决方案的必要性。

Ice Ice：具有自定义功能的 macOS 开源菜单栏管理器​

  • "Ice Ice "是一款 macOS 菜单栏管理工具，允许用户使用 Command + 拖动来隐藏、显示和重新排列菜单栏项目。
  • 它提供自定义间距和菜单栏外观自定义等功能，并计划在今后的更新中添加更多功能。
  • 该工具需要 macOS 14 或更高版本，可手动安装或通过 Homebrew 安装，并根据 MIT 许可提供。

反应​

  • 讨论的重点是 macOS 菜单栏管理工具，包括 Bartender、Ice、Dozer 和 Hidden Bar，以及用户使用这些应用程序的体验。
  • 有人担心 Bartender 最近被一家可信度较低的公司收购，从而导致潜在的隐私和透明度问题。
  • 用户将 macOS 的易用性和窗口管理与 Windows 和 Linux 等其他操作系统进行比较，讨论是否需要第三方工具来提高工作效率，以及 macOS 用户界面的一致性。

安全问题引发争议后，微软将召回功能改为可选功能​

  • 在安全问题引起反响后，微软将记录用户活动以进行人工智能分析的 "召回 "功能改为 "选择加入 "设置。
  • 批评者曾将 Recall 称作潜在的间谍软件，称其存在未经授权访问敏感数据的风险；现在，用户需要通过 PIN 码或生物识别技术进行身份验证，才能启用或访问 Recall 数据，这些数据将保持加密状态。
  • 尽管发生了这些变化，但隐私风险依然存在，尤其是在法律方面。在微软发生一系列安全事件后，首席执行官萨蒂亚-纳德拉（Satya Nadella）强调安全是重中之重。

反应​

  • 由于用户对隐私和安全问题的严重关切，微软将默认禁用 "召回 "功能。
  • 批评者认为，Recall 捕捉到了电子邮件和密码等敏感信息，将其比作侵入性的浏览器历史跟踪，反映了隐私意识淡薄这一更广泛的问题。
  • 用户对科技公司的数据处理方式表示不信任，并因隐私问题考虑使用 Linux 等替代方案。

GPT-4o 如何编码图像：深入了解标记化和嵌入策略​

  • Oran Looney 撰写的文章 "A Picture is Worth 170 Tokens: How Does GPT-4o Encode Images? "探讨了 GPT-4o 处理每张 512x512 像素的费用为何为 170 代币，相当于约 227 个单词。
  • 它将 GPT-4o 的先进图像编码策略与 CLIP 的简单方法进行了对比，并强调了卷积神经网络（CNN）在图像数据方面的有效性。
  • 文中讨论了 GPT-4o 在基于网格的图像分析方面的性能，提出了金字塔改进策略，并对其 OCR 功能进行了推测，认为它可能会使用像 Tesseract 这样的外部引擎。

反应​

  • 讨论强调了对现代开源 OCR（光学字符识别）解决方案的需求，并建议使用 PaddleOCR 等替代方案，因为与 Tesseract 等过时的工具相比，PaddleOCR 的速度和准确性都更高。
  • 报告批评了在 OCR 任务中使用大型语言模型 (LLM) 的低效率和高成本，并将苹果公司的 OCR API 作为非开源选项，重点介绍了各种 OCR 工具的用户体验以及文档和云服务成本方面的问题。
  • 对话还深入探讨了一些高级话题，如使用 VQVAE 等模型进行图像标记化、图像嵌入的计算复杂性以及人工智能的未来趋势，并就 GPT-4 的图像处理能力和提高复杂文本 OCR 精确度的必要性展开了讨论。

σ-GPTs：自回归模型中的动态阶次提高效率​

  • 论文 "σ-GPTs：自回归模型的新方法 "介绍了一种新方法，它挑战了自回归模型（如 GPT）中从左到右的传统固定顺序。
  • 通过对输出进行位置编码，该模型可以动态调整每个样本的生成顺序，从而对任意标记子集进行采样和调节。
  • 这种方法通过剔除策略实现了高效的多标记采样，大大减少了各种领域的模型评估和生成步骤的数量。

反应​

  • 论文 "Σ-GPTs：自回归模型的新方法 "一文介绍了一种新颖的 GPT 模型训练方法，该方法涉及输入标记的随机排列和双位置编码。
  • 这种方法可以并行预测缺失词块，同时计算条件概率，并使用剔除抽样方法生成填充词块，从而可能提高效率和能力。
  • 虽然Σ-GPT 与 XLNet 等模型相似，但它引入了双位置编码和突发采样等独特元素，并讨论了其应用和局限性，包括句子连贯性和幻觉问题。

惠普 BIOS 更新导致 ProBook 445 和 455 G7 笔记本电脑无法使用，用户寻求解决方案​

  • 在线社区论坛讨论硬件和软件主题，包括笔记本电脑和打印机等各种设备的产品支持。
  • 最近的一次 BIOS 更新导致惠普 ProBook 445 和 455 G7 笔记本电脑无法使用，由于惠普缺乏回应和对保修期外设备维修成本的担忧，用户感到非常沮丧。
  • 用户分享了一些解决方案，如刷新 BIOS 芯片、联系惠普进行维修，并建议禁用未来的 BIOS 更新以防止出现类似问题。

反应​

  • 惠普因 BIOS 更新错误导致笔记本电脑 "死机 "而备受批评，这反映出惠普一直存在质量问题和客户服务不善。
  • 用户们讨论了 BIOS 更新的风险、双 BIOS 系统的缺失以及《计算机欺诈和滥用法》（CFAA）可能涉及的法律问题。
  • 人们将惠普与苹果和 Framework 等品牌进行了比较，苹果和 Framework 因其可靠性而备受赞誉，而惠普的质量则被认为在下降，尤其是在卡莉-菲奥莉娜（Carly Fiorina）领导惠普之后。

OpenSSH 添加新功能，惩罚重复失败的身份验证尝试​

  • 2024 年 6 月 6 日，Damien Miller 为 OpenBSD 的 sshd(8) 引入了两个新的配置选项：PerSourcePenalties 和 PerSourcePenaltyExemptList。
  • 这些选项旨在通过暂时阻止违规 IP 地址来惩罚不良客户端行为，如重复失败的身份验证尝试或导致 sshd 崩溃的操作。
  • PerSourcePenalties 将在即将发布的 OpenBSD 7.6 中默认启用，建议管理员仔细配置这些设置，以避免阻塞合法流量，尤其是在处理来自 NAT 或代理服务器后面的连接时。

反应​

  • 争论的焦点是旨在惩罚不良行为的新 OpenSSH 选项，其公平性和有效性令人担忧，尤其是在 IPv6 的情况下。
  • 大家一致认为 SSH 密钥比密码更安全、更方便，并讨论了 SSH 证书、密钥管理以及 PKCS#11 和 VPN 等增强安全性的替代方案。
  • 对话中还谈到了 OpenBSD 为保证安全而尽量减少代码复杂性的理念，与 OpenSSH 的可配置性形成鲜明对比，以及取消密码验证的潜在影响。

CPU 能量表：在 Linux 上精确监控英特尔 CPU 功耗​

  • CPU Energy Meter 是一款 Linux 工具，旨在使用 RAPL 功能监控英特尔 CPU 的功耗，该功能从 Sandy Bridge 处理器开始提供。
  • 它由慕尼黑 LMU 开发，可跟踪不同领域（CPU 包、内核、非内核、内存和平台）的功耗使用情况，开销可忽略不计，并根据 BSD-3 条款获得许可。
  • 通过 Debian/Ubuntu 的 PPA 或 GitHub 上的 .deb 包，安装非常简单，只需设置适当的权限，即可在没有 root 访问权限的情况下运行。

反应​

  • 讨论重点是测量英特尔和 AMD CPU 能源消耗的工具和方法，包括 "CPU 能源表"、英特尔的 RAPL 接口、"perf"、"turbostat "和 AMD 的 uProf。
  • 出于安全考虑，AMD 的能量测量功能已从 Linux 内核（5.13 版）中删除，建议使用 Astron 的功率测量工具包等替代品。
  • 对话还讨论了英特尔能源测量的准确性、全系统功耗测量的挑战，以及 PROCHOT 条件导致的 CPU 节流问题，并提出了缓解建议。

为什么多线程会降低代码速度？AWS 工程师的见解​

  • AWS 工程师 Marc Brooker 在一篇博文中以生日悖论模拟为案例，讨论了多线程编程的复杂性。
  • 他发现，由于上下文切换和 L1 缓存缺失，多线程使仿真速度变慢，而这是通过 Linux 的 perf 工具识别出来的。
  • 改用可重入随机数发生器 (random_r)后，性能有所提高，这说明多线程程序的效率有时会低于单线程程序。

反应​

  • 讨论强调了在编程中使用线程的低效性和复杂性，尤其是在全局共享状态（如random()）下，以及标准库（如 libc）在多线程环境中的局限性。
  • 与会者提出了 libc 定制替代方案、管理副作用的更好抽象方法，并探讨了函数式编程和操作系统级安全措施的优势和挑战。
  • 重点是多线程随机数生成器（RNG）中确定性行为的重要性、线程本地状态的使用，以及全局与独立伪随机数生成器（PRNG）的争论。

探索 "坏 0"：汤姆-7 的三种独特方法​

  • 在 SIGBOVIK 2024 会议记录中，可以通过 Knuth 和 Epsom 的版本探索 "Badness 0"，由于显示错误，最好在 Chrome 浏览器中查看。

  • 粉丝们欣赏他的创造力和深度，像 NES 播放 SNES 游戏这样的著名项目都是重点。
  • 他采用异想天开的方式，包括故意出错来吸引观众，往往能带来深刻而幽默的见解，因此赢得了一批忠实的粉丝。

如何在 Manifest V3 过渡后继续在 Chrome 浏览器上使用广告拦截器​

  • 用户可以通过启用 ExtensionManifestV2Availability 密钥继续在 Chrome 浏览器和 Chromium 浏览器上使用广告拦截器，尽管谷歌已转向 Manifest V3，而后者缺少 webRequestBlocking API。
  • 启用此密钥的说明因操作系统而异：Linux 和 ChromeOS 需要使用终端命令，Windows 使用 regedit，而 MacOS 则需要使用终端命令（未经测试）。
  • 即使 Manifest V2 扩展的官方支持终止，该变通方法也能利用企业策略来维持广告拦截器的功能。

反应​

  • GitHub 上的一篇文章讨论了在谷歌转向限制广告拦截器的 Manifest V3 后，Chrome 浏览器和 Chromium 浏览器仍能保持广告拦截器功能的问题，并为开发人员和精通技术的用户提出了临时解决方案。
  • 用户们讨论了转用火狐浏览器的问题，尽管火狐浏览器因过去的更改而不被信任，但仍然支持广告拦截器，他们还讨论了 Edge、Safari、Pi-hole 和 DNS 级拦截等替代方案。
  • 有人对变通方法的可持续性、基于 Chromium 的浏览器的主导地位以及谷歌的变化对广告拦截器的影响表示担忧，并提到了 Brave 和 Arc 等浏览器的支持。

尽管存在推进器问题，波音公司的 "星际客机 "仍成功对接国际空间站​

  • 波音公司的 "星际客舱 "在多次尝试失败后成功发射，将美国国家航空航天局宇航员布奇-威尔莫尔和苏尼-威廉姆斯送入低地球轨道。
  • 这项任务是美国国家航空航天局（NASA）耗资 43 亿美元的 "商业乘员计划 "的一部分，旨在测试 Starliner 将乘员送往国际空间站（ISS）的能力。
  • 尽管推进器出现了技术问题，但太空舱还是与国际空间站进行了对接，宇航员们将于 6 月 8 日对星际客机进行现场虚拟参观。

反应​

  • 波音公司的 "星际客机 "尽管经历了多次推进器故障，但仍成功地与国际空间站对接，延续了以往任务中出现类似问题的趋势。
  • 对接后，工程师们发现了第四次氦气泄漏和尚未解决的推进器问题，这让人们对飞船在未来载人飞行任务中的可靠性产生了担忧。
  • 讨论重点对比了波音公司的传统方法和 SpaceX 公司的迭代、风险容忍战略，指出了对波音公司质量下降的批评，以及削减资金对航天知识和任务安全的影响。

我如何在 BIOS 更新失败和技术支持中断后恢复 HP Envy 17​

  • 该文件概述了作者在 BIOS 更新失败导致惠普 Envy 17-ae110nr 笔记本电脑无法使用后对其 BIOS 内存芯片进行重新编程的过程。
  • 作者使用原理图、STM32 开发板和 SPI 通信等工具提取并重新刷新 BIOS 固件，经过多次尝试，最终恢复了笔记本电脑。
  • 该文件为其他面临类似问题的人提供了指导，并强调了对惠普客户服务的担忧，特别是有关第三方组件导致保修失效的问题。

反应​

  • 一位 GitHub 用户分享了他们恢复一台坏掉的惠普笔记本电脑的经验，引发了关于保修欺诈、惠普产品声誉以及使用 Bus Pirate 和 Raspberry Pi 等工具恢复 BIOS 技术的讨论。
  • 对话凸显了现代硬件维修所面临的挑战，用户分享了不同品牌的类似问题，以及对保修服务的不满，尤其是索尼的保修服务。
